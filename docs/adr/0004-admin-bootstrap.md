# 0004 · 首个管理员的引导创建

日期：2026-10-18
状态：已采纳

## 背景

C7 规定全站只有一条 `admins` 记录，且没有注册接口。契约没有说明第一条记录从哪来，
但 G1 要求"5 次错误锁定 30min""未登录 401/1000"等断言都必须先有一个可登录的账号。

## 选项

1. **迁移里插入固定账号**：口令哈希必须写死在 SQL 里，等于把默认口令入库，最差。
2. **独立 CLI（`cmd/admin`）**：灵活（可重置口令），但多一个 main 包，与"main.go 仅
   initialize → run"的约束有张力，且部署脚本要多一步。
3. **启动时按环境变量幂等创建**（本决定）。

## 决定

采用 3，实现见 `apps/server/initialize/admin.go`：

- 仅当 `admins` 表为空、且 `BLOG_ADMIN_USERNAME` 与 `BLOG_ADMIN_PASSWORD` 都非空时创建。
- 口令长度 ≥16（§9），argon2id（m=64MiB, t=3, p=2），只存哈希，绝不写日志。
- 创建动作与 `auth.admin_bootstrap` 审计记录在同一事务里提交。
- 表非空时完全跳过：环境变量留在 `.env` 里也不会重置口令。

## 后果

- 部署只需在首次 `docker compose up` 前填两个变量；建好后建议删除 `BLOG_ADMIN_PASSWORD`。
- 忘记口令时的重置路径：停容器 → 用一次性容器执行一段匿名 SQL 删除 `admins` 行 → 重新设置
  环境变量启动（或后续 D14 的管理端改密）。这段操作必须在 runbook 里注明"会同时清空会话"。
- 环境变量是唯一的口令入口；口令不会出现在 `config.yaml`（该文件会进镜像）。
